# Existing-account journeys

Use these journeys to check Mapbox connection in a standalone installation and a
local development checkout. Account creation is outside this walkthrough.

## 1. Prepare the app

### Downloaded binary

For the Linux x86-64 archive:

```sh
mkdir -p "$HOME/.local/bin"
tar -xzf "$HOME/Downloads/mapbox-tui-linux-amd64.tar.gz" -C "$HOME/.local/bin"
mapbox-tui --help
```

The archive contains only `mapbox-tui`. Go and Make aren't needed to run it. Check that
help lists `--no-provider`. The current archive is generated by `make package` at
`dist/mapbox-tui-linux-amd64.tar.gz`; it hasn't been published as a public release yet.

### Local development

From the checkout root:

```sh
mise exec go@1.27.1 -- make build
./bin/mapbox-tui --help
```

For rebuilding/restarting as source changes:

```sh
mise exec go@1.27.1 -- make dev ARGS="fixtures/example.gpx"
```

Commands below use `mapbox-tui` for the standalone installation and `./bin/mapbox-tui` for
the local build. Substitute your own GPX path for `ride.gpx`.

## 2. Install the optional Mapbox CLI

One installation serves both app builds. Follow the
[official Mapbox installation documentation](https://github.com/mapbox/mapbox-cli#install-a-released-binary).
The optional Tilesets CLI is for publishing datasets and isn't required by `mapbox-tui`.
After installation, verify:

```sh
mapbox --version
```

It installs into `~/.local/bin`, already on PATH in this environment, and checks
the archive checksum. Versioned acquisition follows the
[dependency/security reference](https://github.com/lirantal/npm-security-best-practices).
It preserves the login already stored under `~/.mapbox/`.

## 3. Check or connect an existing account

| Action | Standalone | Local development |
|---|---|---|
| Check connection | `mapbox-tui auth status` | `./bin/mapbox-tui auth status` |
| Sign into an existing account | `mapbox-tui auth login` | `./bin/mapbox-tui auth login` |

Status should report CLI `ready`, login `usable`, rendering token `valid`, and
Streets `ready`. If it already does, your saved login is connected. Otherwise run
login and complete browser sign-in/MFA for your existing account.

Auth commands show the resolved credential file. On this machine it is
`/home/adam/.mapbox/credentials.json`; `MAPBOX_CONFIG_DIR` can relocate the store.
Mapbox CLI saves/refreshes the OAuth login. `mapbox-tui` retrieves a public rendering
token and keeps it in memory. Neither app build needs a repo token file.

## 4. View a GPX with maps

| Standalone | Local development |
|---|---|
| `mapbox-tui ride.gpx` | `./bin/mapbox-tui fixtures/example.gpx` |

The file opens immediately, then background maps load using the saved login.
Without a connection, the geometry still opens, the footer shows
**No basemap · Mapbox not connected**, and the same notice is echoed once to
stdout. File opening doesn't launch browser login or an authentication prompt.

For file-free browsing, use `mapbox-tui` or `./bin/mapbox-tui`. A missing connection offers
setup or continuing offline.

## 5. Deliberately view offline

| Standalone | Local development |
|---|---|
| `mapbox-tui ride.gpx --no-provider` | `./bin/mapbox-tui fixtures/example.gpx --no-provider` |

Geometry, measurements, elevation and playback work on an empty canvas. No
automatic credential lookup, background tiles or connection notice occurs.
Manual journey coordinates work too. Relaunch without the flag to enable maps.

For a development watcher in this mode:

```sh
mise exec go@1.27.1 -- make dev ARGS="fixtures/example.gpx --no-provider"
```

## 6. Connect from an already-open viewer

This journey applies when the app was launched normally, rather than with
`--no-provider`:

1. Load a GPX while disconnected.
2. Install Mapbox CLI if needed.
3. Press Ctrl-P, filter for **Mapbox account setup**, then Enter. Missing CLI?
   Choose **Installation help** for Mapbox's documentation, then **Check again**
   after installation. A saved usable login can connect without another sign-in.
4. Once the CLI is ready, choose **Sign in to Mapbox** if needed and use your
   existing account in the browser.
5. Check that the terminal returns to the viewer, maps load, and the imported
   files/camera remain in place.

The same steps work in either app build. Rechecking reports success/failure.
Once connected, the palette offers **Mapbox settings** rather than account setup,
and its first action is **Check connection** instead of sign-in. The login operation reports the saved
credential location before returning to the viewer.

For place search, Ctrl-G opens a journey; edit a location and type a place name.
Mapbox search is automatic when connected, after three characters and a short pause.
Ctrl-S retries the query. Unavailable search is greyed out; manual
coordinates/map-centre input, editing and reversal work without an account.

Mapbox settings also includes **CLI telemetry**, off by default. Toggle it only
if you want Mapbox CLI processes launched by `mapbox-tui` to send their usage telemetry.
The shared preference persists across both app builds. An explicit environment
opt-out takes precedence.

## 7. Inspect connection and usage

| Action | Standalone | Local development |
|---|---|---|
| Human-readable report | `mapbox-tui auth status --usage` | `./bin/mapbox-tui auth status --usage` |
| JSON report | `mapbox-tui auth status --usage --json` | `./bin/mapbox-tui auth status --usage --json` |

Expect separate login, rendering and Streets states, plus account/active-token
Vector Tiles usage with UTC dates and generation times. No token strings appear.
Unavailable statistics can coexist with working maps. Counts can lag 24 hours,
include other apps, and aren't an invoice or remaining allowance. Status probes
make a tile request.

## 8. Render or use MCP without the viewer

| Action | Standalone | Local development |
|---|---|---|
| Plain render | `mapbox-tui render ride.gpx` | `./bin/mapbox-tui render fixtures/example.gpx` |
| JSON render | `mapbox-tui render ride.gpx --json` | `./bin/mapbox-tui render fixtures/example.gpx --json` |
| Offline render | `mapbox-tui render ride.gpx --no-provider` | `./bin/mapbox-tui render fixtures/example.gpx --no-provider` |
| Start MCP | `mapbox-tui mcp` | `./bin/mapbox-tui mcp` |

Plain disconnected renders print the short stdout notice. JSON and MCP remain
structured and don't echo an extra line. MCP waits for client requests; local
imports/inspection work offline, while a map render resolves saved credentials
lazily. These commands never launch browser login.

## 9. Log out and reconnect

| Standalone | Local development |
|---|---|
| `mapbox-tui auth logout` | `./bin/mapbox-tui auth logout` |

Logout reports the credential location and removes the shared default CLI login.
Close running viewers/MCP processes before checking a fresh launch: they may
still hold a public token in memory. With no environment token override, a fresh
status reports logged out and a normal GPX launch displays the connection notice.
Run login with the same existing account to reconnect.

Both builds share the same CLI profile. Login through one works for the other;
logout affects that shared login, not the validity of the account's public token.
